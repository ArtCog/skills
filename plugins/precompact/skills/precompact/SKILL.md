# Precompact

Компакт неизбежно теряет часть контекста. Саммари пишет **сжиматель**: он видел
транскрипт, но не работал в нём. Три вещи он роняет системно, и именно они потом
стоят часа:

- **тупики** — что уже пробовали и почему не вышло; без них агент идёт туда снова;
- **решения пользователя дословно** — они сказаны в чате и больше нигде не записаны;
- **точное физическое место остановки** — не «работаем над парсером», а `foo.py:42`.

Этот скилл пишет их до сжатия — рукой того, кто всё ещё помнит.

Блок работы закончен целиком — новая сессия дешевле компакта: запиши итог туда, где
проект держит «на чём остановились» (`STATE.md` или аналог), и начни заново. Этот
скилл для **незаконченной** работы, которую надо пронести через сжатие.

## 0. Какой компакт

| Режим | Когда | Что пишет |
| --- | --- | --- |
| **Обычный** (по умолчанию) | короткое продолжение в этом же чате | `PRECOMPACT.md` в scratchpad (шаг 3) |
| **С задачей** | пользователь сказал «с задачей», «таск», «для другой сессии», «чтобы ничего не потерять»; или впереди много шагов, а его решения и предложения агента есть только в чате | то же **плюс** файл задачи в проекте (шаг 3б): по нему продолжит и эта сессия после сжатия, и любая новая |

Не ясно, какой нужен, — один вопрос: «обычный компакт или с задачей?».

**Без хука — всегда «с задачей».** Записку из scratchpad после сжатия вливает обратно
хук `precompact-restore.sh`; он ставится вместе с плагином в Claude Code. В Codex и
других агентах его нет, и если пути к scratchpad в окружении нет, тоже. Тогда файл
задачи в проекте и есть точка продолжения: после сжатия первым делом читать его.

## 1. Довести до целого

Компакт посреди полушага — худший случай: файл в промежуточном состоянии, а память
о том, каким он должен стать, ушла. Сначала целостность, потом запись.

- **Ничего нового не начинать.** Даже мелкого «заодно».
- **Правка на середине** — довести файл до рабочего состояния или откатить. Не
  оставлять половину рефактора: половина выглядит как законченный код и врёт.
- **Фоновые задачи** — дождаться, если минуты. Иначе записать id и путь к output.
- **Прогнать проверку**, которая показывает, где стоим: тесты, типы, сборка,
  один curl. Её вывод — факт для записки, а не воспоминание о нём.

Доводить дольше пары минут — не доводить: записать как незавершённое, точно назвав
файл и строку.

## 2. Снять показания с диска

Память уже плывёт — она и есть то, что сжимают. Смотреть, а не вспоминать:

- есть git → `git status --short` и `git diff --stat`
- нет git → `ls -lt` по рабочей папке, самый свежий файл и есть точка остановки
- фоновые задачи → их id

## 3. Записать записку

Файл: `<scratchpad>/PRECOMPACT.md` — scratchpad **этой** сессии, путь есть в
окружении. Хук вливает его обратно сразу после сжатия; класть в другое место —
значит не вливать. В режиме «с задачей» его первая строка после заголовка — путь к
файлу задачи: после сжатия читать его первым.

```markdown
# PRECOMPACT — <задача одной строкой>
<ГГГГ-ММ-ДД ЧЧ:ММ>

## Следующее действие
Одна строка: файл:строка или команда. «Дописать ветку else в hook.sh:31», а не
«продолжить работу над хуком».

## Состояние на диске
Что изменено и сохранено, что нет, что не проверено. Вывод проверки из шага 1.
Фоновые задачи: id + путь к output.

## Решения пользователя
Дословно. Что выбрал, что забраковал и по какому признаку. Только из этого чата.

## Тупики
Что пробовали → почему не сработало. Чтобы не пойти туда второй раз.

## Дорого добытые факты
Пути, версии, что подтвердилось и что опровергнулось. Плюс файлы, которые уже
прочитаны и не менялись — путь + вывод одной строкой, чтобы не читать заново.
```

Пустые секции убирать. Потолок — **60 строк**: записка, которую саму нужно сжимать,
бессмысленна.

## 3б. Файл задачи (режим «с задачей»)

Scratchpad живёт с сессией; задача должна пережить и её. Поэтому файл — в проекте.

- **Где:** там, где проект уже держит задачи (`docs/tasks/`, если есть; иначе
  создать `docs/tasks/` в корне проекта). Имя `ГГГГ-ММ-ДД-<slug>.md`. Есть уже файл
  этой работы — обновить его, второй не заводить.
- **Как найти из новой сессии:** одна строка со ссылкой там, где проект держит «что
  дальше» (`STATE.md`, очередь задач, раздел «Open»). Без неё задачу никто не
  откроет.
- **Разделы** (пустые убирать):
  - *Цель* — что и зачем, 1–3 строки.
  - *Статус* — что сделано и чем проверено, что нет; пути.
  - *Решения пользователя* — принятые им предложения агента дословно, это и есть
    договорённость.
  - *Где что лежит* — таблица путей: отчёты, черновики, данные.
  - *Следующие шаги* — по порядку; у каждого действие и признак «готово».
  - *Тупики* — что не работает и почему.
  - *Открытые вопросы к пользователю.*
- **Только самое важное:** потолок около 150 строк, сверх него — только то, что
  пользователь попросил записать дословно; пересказа разговора нет; то, что лежит в
  файлах, — ссылкой.
- **Проверка:** перечитать глазами новой сессии без этого чата. Можно начать
  следующий шаг, ничего не спрашивая? Нет — дописать недостающее.

## Что не писать

- **То, что лежит на диске.** План, спека, коммит, `STATE.md` — сослаться путём.
  Пересказ протухнет первым, а места займёт больше всего.
- **Пересказ разговора.** Это работа сжимателя, он её сделает. Здесь — только то,
  чего он не может знать.
- **Ключи, токены, содержимое `.env`** — именем переменной.
- Язык — тот же, что в чате.

## 4. Отдать ход

Сказать одной строкой: записка готова (в режиме «с задачей» — и путь к задаче),
можно `/compact`. Компакт запускает пользователь — сам не вызывать.
