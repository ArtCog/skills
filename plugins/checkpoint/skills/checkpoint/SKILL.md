# Checkpoint

Пользователь не просил — не выполнять, спросить. Момент «блок закончен» выбирает он.

Записать текущее состояние проекта в `STATE.md`, чтобы **любой** агент — новая
сессия Claude Code, Codex, Antigravity — вошёл в проект и продолжил с этой точки.

`STATE.md` отвечает на один вопрос: **на чём мы стоим прямо сейчас.** Не что за
проект — это карта, и она лежит в паре файлов, которые есть в каждом проекте:
`AGENTS.md` (содержимое, читают все агенты) и `CLAUDE.md` (строка `@AGENTS.md`,
через неё карту видит Claude Code). Не что я знаю про пользователя — это память.
Не история — это git.

## Процесс

### 1. Определить проект

Проект — это папка, для которой пишем состояние: один репозиторий, один инструмент,
одна работа. **Корень воркспейса проектом не является** — это контейнер для всех
проектов сразу.

Случаев ровно два.

**Пользователь назвал проект** — аргументом команды или просто словами в реплике.
Ищем папку с таким именем в корне воркспейса, затем на уровень глубже в папках-
разделах. Это стартовые точки, а не ограничение: назвал путь или папку вне их —
берём её.

Имя почти всегда неточное: его называют на слух, часто на другом языке, чем имя
папки, и без префиксов вроде года. Сопоставлять по звучанию и по части имени, а не по
точному совпадению. Нашлось несколько — показать список и спросить, какая.

**Не назвал** — берём текущую рабочую папку и поднимаемся от неё до корня проекта:

- внутри git-репозитория → `git rev-parse --show-toplevel`
- внутри папки-раздела → сама папка работы, а не раздел
- рабочая папка и есть корень воркспейса → проект не определён, спросить какой

Не сходится — спросить одной строкой, не гадать. Чекпоинт не в тот проект хуже, чем
отсутствие чекпоинта: он врёт про чужое состояние.

`STATE.md` кладём в корень найденной папки, рядом с картой проекта.

### 2. Создать или обновить — две разные ветки

**Файл есть** → прочитать целиком. Это **обновление**, а не перезапись: то, что не
изменилось, остаётся дословно. Особенно «Не трогать» — там накопленные грабли,
их не сокращать. Дату в шапке обновить всегда.

Если в проекте **нет git** — перед перезаписью сохранить одно поколение:
`cp STATE.md STATE.md.bak`. Плохой чекпоинт там иначе необратим, откатывать нечем.
В git-репозитории этого не делать: откат даёт сам git, лишний файл только мусорит.

**Файла нет** → создать по шаблону из шага 3. Это нормальный случай, а не ошибка:
у проекта просто ещё не было чекпоинта.

Перед первым созданием — осмотреться, а не писать по одному разговору. Разговор мог
начаться с середины, и половина состояния в него не попала. Посмотреть:

- `AGENTS.md` / `CLAUDE.md` проекта — что это вообще за проект
- планы, если есть: `PLAN.md`, `PLAN.local.md`, `canvas.json`, `preproduction/`
- **есть git** — `git log --oneline -10` и `git status`: что делали и что не дошло
- **нет git** (медиа- и контент-проекты часто живут обычными папками, без репозитория) —
  историю заменяют даты изменения: `ls -lt` по корню проекта и
  `find . -type f -mtime -7 -not -path '*/.*'`. Самый свежий файл почти всегда и
  есть то, чем занимались последним; сравнение дат соседних файлов показывает
  порядок работы не хуже коммитов
- рабочие папки — **пустая папка это факт**. `raw/` без файлов означает «съёмка
  не начата», и это надёжнее любой формулировки по памяти

Проверяемый факт сильнее воспоминания. Пишешь «готово» — покажи, чем подтверждается.

### 3. Записать

Шаблон ниже. Пустые секции убирать, не оставлять заголовок с прочерком.

```markdown
# STATE — <имя проекта>

Обновлено: <ГГГГ-ММ-ДД> · Статус: в работе | пауза | закрыт

## Где стоим
2-4 предложения. Что уже работает и проверено, что только что закончили.
Проверено — значит есть доказательство (тест прошёл, curl вернул 200), а не «сделал».

## Следующий шаг
Одно конкретное действие, с которого начинает следующая сессия.
Не список желаний. Если шагов правда несколько — первый, потом остальные списком.

## Открытые решения
- вопрос → кто решает или чем заблокировано

## Не трогать
Грабли, на которые уже наступали. Только живые: то, что стало постоянным
правилом проекта, переезжает в AGENTS.md и отсюда убирается.

## Артефакты
- план → путь
- отчёт → путь
```

### Правила содержания

- **Не дублировать то, что уже записано.** Есть `PLAN.local.md`, спека, тикет,
  коммит — сослаться путём, а не пересказывать. Дубль протухнет первым.
- **Конкретика вместо статуса.** «Ждём ответа, какой таймаут ставить в ретраях» —
  полезно. «Работа продолжается» — мусор.
- **Даты абсолютные.** «Вчера», «на прошлой неделе» через месяц не читаются.
- **Размер.** Писать столько, сколько есть состояния. Потолок — 200 строк, в крайнем
  случае 300. Держится он за счёт того, что вещи из файла **уходят** в две стороны:
  решённый вопрос удаляется (историю помнит git), а грабля, ставшая постоянным правилом
  проекта, переезжает в `AGENTS.md`. Упёрся в потолок — разгружать эти две секции, а не
  ужимать смысл. Частые чекпоинты файл не растят: «Где стоим» и «Следующий шаг»
  перезаписываются.
- **Не выдумывать.** Не помнишь, чем кончилось — так и написать: «не проверено».
  Ложная уверенность в STATE.md хуже, чем его отсутствие.
- Язык — тот, на котором с тобой говорит пользователь. `STATE.md` читает он, а не
  посторонний.

### 4. Карта проекта

Нет `AGENTS.md` в корне — завести вместе с `STATE.md`: короткая карта из того, что уже
выяснено при осмотре. Без заглушек, пустая карта хуже отсутствующей. Рядом `CLAUDE.md`
из одной строки `@AGENTS.md` — Claude Code читает только его. Содержимое не
дублировать, иначе файлы разъедутся.

`AGENTS.md` уже есть — не трогать, только дописать ссылку на `STATE.md`.

Не через `/init`: он пишет содержимое в `CLAUDE.md`, то есть наоборот.

### 5. Гитигнор

Если проект — публичный репозиторий, добавить `STATE.md` в `.gitignore`
(это рабочие заметки, не документация). Локальный проект без remote — не трогать.

### 6. Закрыть блок

Показать записанное и сказать прямо: блок закрыт, можно начинать новую сессию.
Если контекст уже большой — напомнить, что новая сессия дешевле компакта.
